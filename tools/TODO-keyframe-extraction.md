# 视频关键帧截取

## 待实现

目前视频剪藏只提取 AI 字幕（yt-dlp `--sub-lang ai-zh`），字幕转成带时间点的 Markdown 文本。
但**对于教程类视频，关键截图往往比文字更浓缩、更精准**——代码截图、架构图、UI 操作步骤等，一张图胜过百字描述。

## 为什么有价值

| 场景 | 纯字幕的问题 | 关键帧能解决 |
|------|-------------|-------------|
| IDE 教程 | "点击 File 然后 New Project" 文字很啰嗦 | 截图直接显示菜单位置 |
| 架构图讲解 | 口述 "左边是 A 右边是 B" | 架构图一目了然 |
| 代码演示 | AI 字幕识别代码可能有错字 | 代码截图可 OCR 或直接存档 |
| 设计教程 | 描述颜色/布局很困难 | 截图保留完整视觉信息 |

## 实现思路

### 帧选择策略

1. **场景变化检测**（ffmpeg `select='gt(scene,0.3)'`）
   - 对比相邻帧差异，差异超过阈值时截取
   - 优点：自适应内容节奏
   - 缺点：纯文字讲解阶段可能截到黑屏/过渡帧

2. **等间隔采样 + 去重**
   - 每 10-30 秒截一帧
   - 用 perceptual hash 去除相似帧
   - 优点：实现简单
   - 缺点：可能错过关键瞬间

3. **字幕时间点关联**
   - 利用已有字幕时间戳，在每个字幕段落起始点截图
   - 优点：与文字内容对齐
   - 缺点：字幕分段粒度不一

4. **混合策略**（推荐）
   - 场景变化检测为主
   - 字幕时间点为辅
   - 去重过滤 + 质量筛选（排除模糊/过暗帧）

### 技术路径

```
yt-dlp 下载视频（已有 browser cookie 绕过 412）
    ↓
ffmpeg 提取关键帧
    ↓
可选：OCR 识别帧中文字（Tesseract）
可选：AI 图像描述（需要多模态模型）
    ↓
保存图片到 90 Attachments/Clips/{note-id}/
    ↓
在 Markdown 中按时间点插入图片
```

### 示例 ffmpeg 命令

```bash
# 场景变化检测（阈值 0.3）
ffmpeg -i video.mp4 \
  -vf "select='gt(scene,0.3)',scale=1280:-1" \
  -vsync vfr \
  -frames:v 20 \
  -q:v 2 \
  frames/frame_%04d.jpg

# 结合字幕时间点（每段字幕起始截一帧）
# 需要解析字幕 JSON 后生成 seek 列表
ffmpeg -ss 00:01:05 -i video.mp4 -frames:v 1 -q:v 2 frame_001.jpg
```

### 存储结构

```
90 Attachments/Clips/
  {note-id}/
    frames/
      [00:01:05]-scene.jpg
      [00:03:22]-code-demo.jpg
      [00:05:47]-architecture.jpg
    video.mp4  （可选保留）
```

### Markdown 中的呈现

```markdown
## 视频关键帧

![00:01:05 - 介绍项目结构]([00:01:05]-scene.jpg)
![00:03:22 - 代码演示]([00:03:22]-code-demo.jpg)
![00:05:47 - 架构图解]([00:05:47]-architecture.jpg)
```

## 难点

1. **帧选择质量**：场景变化检测的阈值需要调优，太低截太多无意义帧，太高漏掉关键内容
2. **存储占用**：一个 8 分钟视频可能产生 20-50 张关键帧，每张 200-500KB，总计 4-25MB
3. **OCR 准确率**：视频截图中的小字体、代码字体识别率不高
4. **AI 图像描述成本**：每张截图调用多模态模型的 token 消耗
5. **与字幕对齐**：字幕时间点和画面变化不一定同步
